# Recurring visit planner — read-only saved-status summary preview (PR #232)

## Why

PR #231 introduced a safe single-visit saved-status TXT download. Before downloading, a manager should be able to read that **same status summary** inside LMS, particularly on a phone where repeated file downloads are inconvenient. This adds an optional **read-only, selectable** preview. No new booking capability, server query, data export, or count calculation.

## User experience

- In **Schedule → Repeating visit planner → Reviewed proposed visit details**, keep the existing **Download reviewed visit TXT**, **Download reviewed visit status TXT**, **Copy reviewed visit**, and **Preview visit note** buttons unchanged. The first and last two remain strictly date-only.
- Add a native **Preview saved status summary** button that starts collapsed (`aria-expanded=false`). Expanding changes its label to **Hide saved status summary** and shows a separate **read-only text area** labeled **Selectable saved appointment status summary — NOT BOOKED**. It uses the existing dark/light theme-aware, narrow-phone-safe `.recurring-visit-note-preview` styles, 44px touch buttons, and semantic label/input pairing.
- The new textarea value is directly generated by the *same pure, strictly validated* `recurringVisitReviewedSavedStatusText` function used by #231's TXT download. It includes only one selected date, original one-based visit ordinal, existing non-archived authorized saved appointment total, Saved categories (Scheduled/In progress/Completed/Cancelled/Other), fixed classification, and **NOT BOOKED / availability not confirmed** caveats. No raw saved records, personal/customer/work identifiers, appointment times, names, free-form status strings, resources, or booking claims.
- This preview does **not** call clipboard APIs or download anything: users can select the text or long-press on phones. A separate button leaves the existing date-only note and sharing/copy semantics unchanged. Both previews may be shown independently and are not stored.
- The preview state is local `visibleStatusNoteKey`, tied to `planKey + reviewed date`. It closes on:
  - read-only review of another proposed date
  - manual re-anchoring by Previous day, Next day, or Schedule date input
  - recurrence interval or count changes (even after restoring old values)
  - selection of an invalid/overflowing proposed plan or agenda date outside the plan (whole reviewed panel hides).
- When the same selected date's authorized saved counts change after an explicit manual appointment Save/Cancel, the generated text reflects the latest already-rendered per-date counts without cached status values.
- Maintain existing strict **2–12 proposed visits**, organization isolation, role restrictions, no-login demo, accessible themes, 24-demo-session cap, and all resource conflict checks. No change to ForgeOS or unrelated projects.

## Verification

- Extend the **existing** Playwright scheduling scenario for the two fictional business workspaces without adding sessions. The preview starts collapsed, opens a read-only textarea, and its exact value matches #231's downloaded TXT **excluding its final file newline**; check privacy and manual copy hint. Closing removes textarea and resets `aria-expanded`.
- When recurrence changes to exclude the agenda date, the entire focused panel and preview disappear. Restoring the old recurrence must not resurrect the previous expanded note.
- In twelve-date Compact mode, it still opens and shows the correct original visit ordinal and availability disclaimer while date cards are hidden.
- An invalid/overflowing recurrence hides the preview as it does the entire focused panel.
- After the test's **one explicit manual Scheduled appointment Save**, the newly rendered preview matches the current downloaded TXT, including refreshed saved statuses and the unchanged NOT BOOKED disclaimer.
- The existing pure `recurringVisitReviewedSavedStatusText` unit tests from #231 already validate strict date membership, safe-integer status counts, classifications and privacy; the current PR adds no second formatter and needs no new unit tests.
